# ЛР3. Текстовое и JSON-представление

Вариант: **Audit**.

## Что дано

Предметные объекты, внешний API и вспомогательные типы уже подготовлены. В `app/domain/formatters.py` даны заготовки общего интерфейса и двух исполнителей. Их поведение и основной метод `AuditService.render()` требуется завершить самостоятельно. Сигнатуры сохранены; новые слои и выбор архитектуры не нужны.

## Задание

### Шаг 1. Реализуйте общий интерфейс и два поведения

Реализуйте `AuditFormatter`, `TextAuditFormatter` и `JsonAuditFormatter` с общим `format(event) -> str`.

Для JSON используйте готовый стандартный кодировщик и функцию времени. Возвращайте строку со всеми полями события, не Python-словарь. Сервис должен вызывать `format()`, не выбирать алгоритм по конкретному классу.

### Шаг 2. Соберите путь вызова в `AuditService.render()`

Сначала выберите события через `find()`. Для каждого вызовите форматтер ровно один раз, проверьте строку готовой `format_result()` и верните `tuple`. Чтение и ошибка форматтера не удаляют события. Не выбирайте алгоритм по конкретному классу исполнителя.

### Шаг 3. Проверьте повторное использование

Запишите событие, получите строки, попробуйте повторить ID и добавьте другое событие. Старые строки и данные первого события не меняются.

## Примеры и границы

- Текст для `E1`: `E1|PAYMENT_APPROVED|TX-1`.
- JSON разбирается в ожидаемые поля, включая `details`.
- Кавычки и кириллица в деталях сохраняются.
- Оба результата — строки; исходное событие не меняется.

Последовательности и конфигурации дополнительно проверяются в `tests/test_progression.py`. Прочитайте ожидаемый результат каждого сценария до реализации.

Все проверки открыты: `tests/test_contract.py` и `tests/test_review_contract.py`.
Описание объектов — в [REFERENCE.md](REFERENCE.md), исходные результаты тестов — в [STARTER-STATE.md](STARTER-STATE.md).

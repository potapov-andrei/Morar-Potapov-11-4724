# ЛР1. Событие как объект

Вариант: **Audit**.

## Что дано

Журнал хранит словари; `record()` и `find()` работают, все тесты проходят.

## Задание

Создайте `AuditEvent` и `AuditService`. Подключите готовую фильтрацию к объектам событий вместо словарей.

Вид события остаётся значением `event_type`: отдельный класс для каждого вида не нужен. Простой текстовый вывод пока можно оставить в сервисе.

## Примеры и границы

- После записи `E1` для `TX-1` и `E2` для `TX-2` поиск `TX-1` возвращает только `E1`.
- Общий порядок — `E1`, затем `E2`.
- Разные хранилища не смешивают события.
- `timestamp` равен переданному времени, а не текущему.

Все проверки открыты: `tests/test_contract.py` и `tests/test_review_contract.py`.
Описание объектов — в [REFERENCE.md](REFERENCE.md), исходные результаты тестов — в [STARTER-STATE.md](STARTER-STATE.md).

# Audit: справка по объектам

Здесь описаны данные и методы сервиса. Нужные изменения для ЛР1 перечислены в [TASK.md](TASK.md).
Часть методов уже реализована в заготовке, остальные добавляются по мере выполнения работ.

## Данные и поведение

Audit хранит события действий: успешную или отклонённую оплату, блокировку карты, изменение лимита. Это учебный журнал, а не система регуляторного аудита.

`AuditEvent(event_id, event_type, entity_id, timestamp, details)` — событие, неизменяемое через публичный интерфейс. Допустимые типы: `PAYMENT_APPROVED`, `PAYMENT_DECLINED`, `CARD_BLOCKED`, `LIMIT_CHANGED`.

Время передаётся явно как `datetime` в UTC с точностью до секунд. Текущие часы не читаются. `details` — плоский `dict[str, str]`, не вложенный JSON. Словарь копируется при создании и чтении; вспомогательная проверка готова.

| Метод | Назначение |
|---|---|
| `AuditService.record(event)` | Сохраняет событие. Повтор `event_id` вызывает `DUPLICATE_EVENT`, даже если данные совпадают. |
| `find(entity_id=None, event_type=None)` | Возвращает `tuple` событий в порядке записи. При двух фильтрах событие должно соответствовать обоим. |
| `render(entity_id=None, event_type=None) -> tuple[str, ...]` | Возвращает текстовые представления найденных событий. |

Общий интерфейс — `AuditFormatter.format(event) -> str`. `TextAuditFormatter` возвращает, например, `E1|PAYMENT_APPROVED|TX-1`. `JsonAuditFormatter` возвращает JSON-строку с ключами `event_id`, `event_type`, `entity_id`, `timestamp`, `details`. Время записывается в ISO-формате с `+00:00`. Порядок ключей JSON не оценивается; содержимое проверяется после разбора.

Хранилище, фильтрация и вспомогательные функции уже реализованы. Обе реализации форматирования возвращают строки, а не разные типы данных.

## Работа с готовым кодом

Обращение к сервису выполняется через `app/api.py`. Разрешённые файлы указаны в [TASK.md](TASK.md).
Проверки используют подготовленные данные и не зависят от работы других групп.

Функции `create`, `make`, `call` и `view` связывают готовый API с реализацией. Используемые ими функции сервисного модуля должны сохранять сигнатуры. Сам `app/api.py` не редактируйте.

До ЛР5 сборка предоставлена готовой. Нужные объекты могут создаваться в сервисном модуле; `assembly.py` менять не нужно.

Режимы сборки — `text` и `json`, с ЛР6 также `key_value`. По умолчанию используется `text`.

## Ошибки и результаты

`DomainError` содержит код ошибки. При отказе проверки состояние объекта не должно меняться.
Ошибка переданной зависимости не заменяется успешным результатом. Конкретные коды и примеры
приведены в задании и открытых тестах.
